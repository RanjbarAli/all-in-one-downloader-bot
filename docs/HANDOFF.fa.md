# تحویل کوتاه

ربات [@granddl_bot](https://t.me/granddl_bot) روی Serverless خود تلگرام مستقر است؛
برای کارکرد آن نیازی به روشن‌ماندن کامپیوتر یا خرید سرور نیست.

حساب مالک: **792399936**. در منوی اصلی روی **User activity** بزنید یا `/admin`
بفرستید. لینک‌ها، شناسهٔ عددی کاربران، وضعیت درخواست و مدیای ذخیره‌شده را می‌بینید.
دکمه‌های Next/Prev همراه شمارهٔ صفحه و تعداد کل، پنج درخواست را صفحه‌بندی می‌کنند.
روی هر درخواست بزنید تا مدیا را با نام کاربری فرستنده، شناسه و لینک منبع ببینید؛
روی آخرین مدیا هم دکمهٔ بعدی/قبلی شماره‌دار قرار دارد. این دکمه برای حساب‌های دیگر نمایش داده نمی‌شود
و درخواست جعلی نیز کنترل دسترسی را دور نمی‌زند.

با Settings → Language زبان فارسی را انتخاب کنید. حد حجم، کیفیت ترجیحی، ارسال
مدیا یا فایل اصلی، توضیحات و نگهداری تاریخچه قابل تنظیم‌اند. کاربر می‌تواند
تاریخچه را حذف یا ذخیرهٔ درخواست‌های جدید را خاموش کند؛ آن رکوردها برای مالک
نیز قابل مشاهده نخواهند بود. این موضوع در اطلاعیهٔ حریم خصوصی ربات توضیح داده شده.

ارسال واقعی تصویر و ویدئوی مستقیم آزمایش شد. عکس پست اینستاگرام نیز به‌صورت فایل اصلی
با اندازهٔ ۱۷۸٬۷۴۸ بایت ارسال شد. تامنیل پروفایل دیگر به‌جای DP اصلی ارسال نمی‌شود. وجود دکمهٔ یک شبکه به معنی تضمین دانلود
ویدئوی آن نیست: YouTube و Vimeo در تست فقط تصویر پیش‌نمایش دادند؛ TikTok،
Dailymotion و نمونهٔ Reddit محدود بودند. وضعیت کامل در VERIFICATION.md آمده است.

منوی فرمان‌ها و توضیحات تنظیم شده‌اند. مشکل فعلی دیتابیس بومی باید برطرف شود؛
تا آن زمان فقط دریافت بدون ذخیره برای حساب مالک فعال است و کارکرد عمومی کامل نیست.
برای توسعه از npm ci، npm test، npm run deploy و npm run migrate استفاده کنید.
اعتبارنامه در حالت محلی مدیریت‌شدهٔ CLI باقی مانده و در سورس ربات نوشته نشده است.
نسخهٔ جامع خواسته‌شده هنوز کامل یا آمادهٔ معرفی به‌عنوان دانلودر همه‌کاره نیست.

متن‌های اضافه کمتر شده‌اند. تنظیمات اصلی فقط زبان و روش ارسال را نشان می‌دهند؛
بقیهٔ گزینه‌ها در More settings هستند. نام کاربری بدون کاراکترهای HTML نمایش
داده می‌شود؛ اگر حساب نام کاربری نداشته باشد، فقط شناسهٔ عددی نشان داده می‌شود.


دکمهٔ View Stories اکنون داخل ربات برای دریافت همهٔ موارد قابل‌دسترسی اقدام می‌کند،
نه بازکردن سایت. در نمونهٔ واقعی، اینستاگرام استوری فعال اعلام کرد ولی هیچ فایلی
نداد؛ ربات همین محدودیت را نشان می‌دهد. عکس HD وب هم فقط ۳۲۰ پیکسل بود و
درخواست عکس اصلی ۴۰۳ گرفت؛ بنابراین ادعای دریافت DP اصلی یا استوری موفق نداریم.
پیج را دوباره بفرستید تا پیام جدید با دکمهٔ دریافت استوری‌ها ایجاد شود.
۵۸ تست خودکار موفق‌اند؛ تست دریافت همهٔ استوری‌ها شبیه‌سازی‌شده است.


به‌روزرسانی آخر: بزرگ‌ترین عکس پروفایل با اندازهٔ معلومِ حداقل ۳۰۰×۳۰۰ پذیرفته
می‌شود؛ ۳۲۰×۳۲۰ هم قابل ارسال است. دکمهٔ استوری پیام پیج را عوض نمی‌کند و نتیجه
را در پیام بعدی می‌فرستد. استخراج HTML و مسیر عمومی GraphQL افزوده شده‌اند؛
طبق درخواست شما برای این تغییرها تست اجرا نشده و موفقیت واقعی استوری تضمین نیست.

مخزن برای انتشار عمومی آماده شده و فایل‌های اعتبارنامه/دیتابیس/کوکی نادیده گرفته
می‌شوند. خودکار روی GitHub منتشر نشده است. پاک‌سازی واقعی دیتابیس به دلیل
Sqlite error انجام نشد. پس از رفع مشکل، دستور زیر همهٔ داده‌های برنامه را پاک می‌کند:
`npm run data:clear -- --confirm-delete-all`
پیام‌های قبلاً ارسال‌شده در تلگرام با این دستور حذف نمی‌شوند.


آخرین شرط مالک: پروفایل باید در هر دو ضلع بزرگ‌تر از ۵۰۰ پیکسل باشد. نسخهٔ ۳۲۰
دیگر ارسال نمی‌شود. در نمونهٔ واقعی فقط ۳۲۰ موجود بود؛ بنابراین دریافت >۵۰۰ یا
استوری موفق نشده است. ۷۰ تست خودکار پاس‌اند؛ تست‌های منو، کنترل‌های مالک و مسیر
استوری با SDK شبیه‌سازی‌شده، جایگزین دریافت واقعی اینستاگرام نیستند.

در /menu مالک، Settings و My downloads و مدیریت/آمار/وضعیت سرویس وجود دارند.
کنترل‌های سقف حجم، تعداد مدیا، فاصلهٔ درخواست، ذخیرهٔ تاریخچه و شبکه‌های فعال
افزوده شده‌اند. تا رفع Sqlite error، ذخیرهٔ تنظیمات و نمایش تاریخچه در محیط واقعی
در دسترس نیست؛ دکمه‌ها پیام محدودیت می‌دهند. پاک‌سازی هم با همین خطا انجام نشد.
